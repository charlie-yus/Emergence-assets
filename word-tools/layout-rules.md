# Word 交付与版面规则（2026-10-25 补充）

本文件来自一次真实返工：用 python-docx 自写脚本排 Word 时，只套用了本 Skill 的页面和字号参数，下面这些规则都没有遵守，导致 66 页里有 30 多页连续是表、一页挤好几张图、目录页码不齐、公式被拆行。以后无论走 LaTeX 还是 Word 路线，都按本文件执行。条文依据学校原件 `assets/school-reference.doc`，与原件冲突时以原件为准。

## 一 分工：内容由作者定，排版只渲染

- 表格的**内容设计**（放哪些模型、几个面板、哪些进附录）属于作者，不属于排版。源稿给出 Markdown 表时，照表渲染，不增删行列、不自行拆面板。
- 源稿只给“【表X】”占位符、要排版方自己从数据抽表时，**先停下来向作者要表格设计**，不要把结果文件的每一行都排进去。
- 排版过程中发现内容问题（数字对不上、行名像程序变量），只记进报告，不改。

## 二 经管类回归表

1. **列＝模型，行＝变量**；系数在上，括号内标准误在下一行；系数保留 3 位小数并带星号。
2. 表底依次为“控制变量”“固定效应”各行（是／否）、“观测值”“组内R²”。**用到什么固定效应就列什么**：只有行业×年份时，必须有“行业×年份固定效应：是”这一行，不能只写“年份固定效应：否”让读者误会。
3. 一个面板对应一组设定；面板标题只写内容（如“面板A：行业与年份固定效应”）。
4. **篇幅预算**：一张表尽量不超过一页；面板少于 3 列时，应合并到相邻面板或改成“行＝设定、列＝固定效应”的转置形式，不要单独成面板、重复整套表尾。全文正文中连续 3 页以上全是表格，说明表格设计有问题，应退回作者。
5. 表内不得出现程序写法：下划线变量名、`code + ind_code^year`、`OLS`/`PPML` 缩写（写中文方法名）、内部任务编号（D1、S8、“12 号”等）。
6. 不适用的格写“—”；表注写清被解释变量、聚类方式、星号含义，不写数据文件名。
7. Markdown 约定：首格以“面板”开头且其余为空的行是面板分隔行（整行合并、左对齐、加粗）；首格为空、其余为括号数的行是标准误行；首格为“分组”的行是该面板内的列标题行。

## 三 插图位置：先文后图

1. 图紧跟在**第一次引用它的段落（“见图X所示”）之后**。
2. 两张图之间必须有正文段落；不得把几张图连续堆在一起，分图除外（分图属于同一张图）。
3. 一页最多放两张图。
4. 当前页放不下时，把这一张图移到下一页顶部，让它后面的正文先上来填满当前页；**不得越过下一张图的引用段落**，也不得把几张图攒成一组整体后移。
5. 图、图题、注与资料来源同页（学校原件要求）。

## 四 留白

- 除学校规定另起页之前的那一页（摘要、英文摘要、目录、结语、参考文献、致谢、附录前）外，正文页底部留白不超过正文区高度的 1/4。
- 处理顺序：先按第三节第 4 条让正文上移；仍不够再把该图等比缩小，最多到 85%，图内文字不小于 9 磅。**不得用堆叠多张图的方式消除留白。**

## 五 目录

- 所有级别使用**同一个右对齐制表位**（版心右边界，A4 文经管为 165 mm），带点线引导；层级只靠左缩进区分。
- Word 目录域必须刷新后再保存或导出；页码以渲染出的 PDF 实际页码为准，逐项核对。
- 验收：所有页码右端在同一条竖线上，偏差不超过 0.5 mm。

## 六 公式与符号

- 公式用 Word 原生公式（OMML）。**用行内 `m:oMath`，不用 `m:oMathPara`**，后者会让公式单独成段，序号被挤到下一行。段落设居中制表位与右对齐制表位，写成“制表符＋公式＋制表符＋（式X）”，一条公式一行，不拆行。
- 变量名不用下划线；多字母变量用正体，单字母下标与希腊字母用斜体。正文中的数学符号也转成行内公式，不保留 `$`、`\mathrm` 等字样。

## 七 数字（学校原件“数字”条）

- 区间用“～”，仅年份区间用“-”（如 2014-2016），不用一字线“—”。
- 千分位用空格（25 631），不用逗号；四位数不加空格。

## 八 交付前检查清单

渲染 PDF 后生成全部页的缩略总览，逐项检查：

- 有没有连续 3 页以上只有表格的地方；
- 有没有一页 3 张以上的图，或两张图之间没有正文；
- 每张图前面是否有引用它的段落；
- 目录页码是否对齐、是否与实际页码一致；
- 公式是否单行、序号是否在右；
- 全文搜索下划线、`^`、内部编号，结果应为 0；
- 非例外页的底部留白是否都不超过 1/4。

检查结果逐项写进报告；做不到的写明原因，不要用“结构核验通过”代替视觉检查。
